# 1.0.2.1_hotfix 设计

## 已确认的发布规则

- 分支、GitHub Release 标题和 tag 均为 `1.0.2.1_hotfix`，tag 不加 v 前缀。
- 应用内显示、package.json、Android versionName、更新清单版本为 `1.0.2.1`。
- iOS CFBundleShortVersionString 为 `1.0.2`，通过递增 CFBundleVersion 区分本次 hotfix。
- Android 本地编译正式签名 APK；iOS 使用现有 GitHub Actions macOS 流程编译未签名真机 IPA，下载到本地。
- 完成验证与构建后发布完整 Release，再将该分支合并并推送至 main。
- 当前已安装的 1.0.2 客户端不识别新 tag，本次需手动安装；新版兼容旧三段版本和新四段 hotfix 版本。
- 四段版本比较遵循数字段顺序，三段版本的第四段视为零。新构建号必须超过已有版本，且在 Android 整数范围内；前端、Gradle 和原生更新插件使用相同规则，校验真实包版本与签名。

## 功能与行为

1. iqdooh 导入：支持官网导出的 `{ version: 1, exportedAt, entries }` 及其条目数组，通过现有合并/覆盖入口导入。保留外部 ID 防止重复导入，转换编号/形态、昵称、真实等级、性格加减项、副技能顺序、食材选择和异色。主技能等级等缺失字段使用现有待补全机制。不能识别的宝可梦跳过并说明数量；不能无提示覆盖为空盒子。已有 native/sdrice/RAE 格式继续可用。
2. 页面内多 tab：移动端每行最多四个，超过四个换行，少于四个均分；修复单个 tab 独占一行。底部五个主导航保留其现有入口。
3. 水滴屏：顶部、底部、横屏侧边和弹窗根据系统安全区域避让，兼顾 Android WebView 的原生窗口 inset，避免重复增加留白。
4. 睡眠规划：移除薰香 +1 控件、说明及数量加成；不修改其他页面的薰香功能。4000 次模拟的糖果按同一进化链共用的糖果合并，展示每次睡眠方案的平均数量（累计糖果 / 4000），不显示糖果总数。拆分睡眠的两段按同一次方案合并；保留研究 EXP 和梦之碎片平均结果。
5. 宝可梦图鉴：显式按数字图鉴编号升序排列，不依赖数据文件更新时间；形态使用对应图鉴编号并采用稳定形态次序。
6. 文案：用户可见的“种族”统一改为“宝可梦”。

## 实现边界

沿用 Vue Composition API、现有 Box 数据结构、Segmented 组件和睡眠计算结果，不引入新的依赖或无关重构。糖果归类逻辑独立于 UI。版本解析、更新清单、原生下载安装校验和发布工作流一起修改，保留发布资产与仓库、tag、哈希、签名之间的校验。

## 验证与发布验收

- 回归 native/sdrice/RAE 导入，新增 iqdooh 普通/形态、真实等级、性格、副技能、食材、缺失字段和重复导入用例。
- 验证三段/四段版本排序、tag 与清单绑定、恶意/不匹配 URL 拒绝和原生构建号一致性。
- 验证糖果进化链合并、拆分方案合并与平均数量。
- 运行相关单元测试、TypeScript 检查、Web 构建，检查窄屏 tab、图鉴顺序和安全区域布局。
- 验证本地 APK 正式签名和包版本；确认云端 IPA 构建成功、下载后包内 iOS 版本/构建号正确。
- Release 同时包含 APK、未签名 IPA 和 update.json，记录本次改动与手动安装限制。
- 使用明确文件列表提交，保留本次开始前的 .gitignore、旧设计文档和未跟踪文档改动。
