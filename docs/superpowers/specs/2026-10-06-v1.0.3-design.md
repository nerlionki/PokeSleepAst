## 架构与共享边界

推荐新增 Taro + Vue 3 + TypeScript 客户端，复用计算和资料。整体迁移现有安卓 UI 到 Taro 会扩大安卓回归风险；完全复制计算逻辑到小程序会导致两套规则分歧，均不采用。

`core/` 承载纯 TypeScript 计算、领域类型、JSON 资料、备份解析和格式转换，以及 OCR 的文本解析、像素处理、图标匹配与模型输入输出处理。共用图片和模型资源由 core 的资源目录统一维护，通过各端构建规则引用或分发，不在两个源目录分别维护。

`app/` 承载安卓界面、Capacitor 存储和文件分享、APK 更新、浏览器图像解码和 ONNX Web 推理适配。迁移计算到 core 后保留必要的兼容导出，减少组件迁移风险。

`wxapp/` 承载 Taro 配置、微信页面、微信存储、文件导入导出、图片读取、推理运行时和版本更新适配。框架专属 API 不进入 core；两端持久化数据使用相同领域格式，但各自保存在本机。

## 小程序功能覆盖

按现有路由和页签逐项验收：

- 宝可梦：图鉴、盒子、展示墙，编辑及 OCR 导入。
- 计划：睡眠、捕捉、宝宝效率、糖果、培养。
- 队伍：队伍计算及比较。
- 资料：营地、树果、食材、食谱、主技能、性格、锅容量。
- 我的：备份导入导出、清空本机数据、引用来源、检查更新。

迁移使用微信可支持的组件和事件，不以页面可编译代替功能可用。文件选择、剪贴板、分享和外部引用在微信 API 下提供可操作入口。计算密集任务保留取消和进度行为，不能直接将浏览器 Worker 当作微信 Worker 使用。

## 更新行为

安卓复用现有 `useUpdateStore` 与更新弹窗，在我的页面放置已有更新设置组件。检查时禁用重复点击，反馈正在检查、已是最新版、可用更新或失败重试；手动检查仍可显示自动提醒中已跳过的版本。

微信使用小程序更新管理器检查当前发布版本，反馈检查结果、下载失败和已就绪；更新就绪后由用户确认应用更新。GitHub APK 更新仅适用于安卓。

## OCR 修复与体验功能

先在原图上复现错误并记录数量标签定位、图标裁剪和候选匹配结果，定位后再修复，不能为单张截图或物种强制写死 ABB。检查淡色未解锁图标、标签遮挡、裁剪偏移及相似图标候选；候选比较应符合物种可选食材与槽位限制。

将原始 `40706B91346C4F34629C83F0E324D450.jpg` 保存到 `ocrTest/`。测试必须覆盖该截图的最终 ABB 组合，同时验证现有截图和合法 ABC 组合，避免把所有第三槽错误改为 B。

小程序使用微信图像 API 和可用的本地推理能力适配现有 OCR 模型，复用 core 的处理和解析逻辑。模型获取及缓存独立于主包，控制包体并明确首次使用的网络需求。对模型不可用、推理失败或设备不支持提供明确提示并保留手动录入，不以虚构结果掩盖失败。具体运行时和资源加载路径在实现计划中经官方文档与技术验证确定；如必须引入外部服务、收费或需要用户配置的托管资源，先询问用户。

OCR 页面注明体验版。构建和自动检查通过不等于用户真机验证通过，交付时列出实际验证范围。
