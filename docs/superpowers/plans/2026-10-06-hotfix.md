# 1.0.2.1_hotfix Implementation Plan

**Goal:** Implement the six approved hotfix changes and publish Android/iOS assets before merging main.
**Architecture:** Keep existing Vue components and Box contracts. Add focused adapters for iqdooh, candy grouping and release version handling; synchronize web, native and CI validation.
**Tech Stack:** Vue Composition API, TypeScript, Vitest, Capacitor, Gradle, GitHub Actions/Xcode.
**Spec:** ../specs/2026-10-06-hotfix-design.md
**Execution:** Implement in this session, as explicitly requested by the user.

## Global constraints
- Branch/tag/title: 1.0.2.1_hotfix; application version: 1.0.2.1; iOS marketing version: 1.0.2 with an increased build number.
- Keep pre-existing edits out of commits. Use existing signing credentials without displaying them.
- No new dependencies or unrelated refactoring. Preserve update URL, digest, package version and signature checks.

## Component map
- Segmented: typed options/model contract, responsive tab arrangement.
- SleepPane: simulation inputs and reward composition; candy aggregation stays in a pure calculation module.
- PokedexPane: filtered list sorted by national dex number and stable form ordering.
- ProfileView: existing import controls and source/result/error copy.
- boxio / iqdoohBox: format discovery and conversion to BoxPokemon, including unresolved field flags.
- version / release: numeric version ordering and exact allowed release tag bindings.

## Review focus
- Unknown forms must not become a different Pokemon; unresolved optional fields must remain marked.
- Repeated exports merge by stable external IDs; malformed imports must not empty existing data.
- Evolution siblings and costume/regional forms may share candy despite separate IDs.
- Narrow viewports and native insets must avoid one tab per line and double padding.
- Legacy installed build codes and future three/four-part versions must preserve update ordering.
