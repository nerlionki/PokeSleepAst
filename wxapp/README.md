# 宝睡助手微信小程序（1.0.3）

Taro 4 + Vue 3 + TypeScript。AppID：`wxa305c12ee6676e08`。

## 编译

在仓库根目录执行：

```powershell
cd wxapp
npm ci
npm run build:weapp
```

开发监听：`npm run dev:weapp`。修改 core 中的界面源文件后重新执行准备/编译命令；生成目录不手动维护。

类型检查：`npm run typecheck`（先执行 `npm run prepare:weapp`）。共享逻辑与 Android 回归：在 `app` 目录执行 `npm ci`、`npm test -- --maxWorkers=1`。

用微信开发者工具导入 `wxapp/`，项目配置已经指向 `dist/`；也可以解压本地的 `app/release/PokeSleepAst-1.0.3-weapp.zip`，直接导入解压后的目录。编译产物含五个主页面、图片分包与计算 Worker 分包。无需配置服务端或网络请求域名。小程序没有手动检查更新按钮。GitHub Release 包含 APK、未签名 IPA 与更新清单；小程序和模型 ZIP 作为本地文件或 Actions artifacts 提供。

## OCR 体验版

1. 将本地 `app/release/PokeSleepAst-1.0.3-ocr-models.zip` 在电脑上解压；也可以直接使用仓库 `core/public/ocr/` 中的模型文件。
2. 把 `det.onnx` 和 `rec.onnx` 两个文件发送到微信会话。不要改名。
3. 小程序“我的”→“导入 OCR 模型”，选择两份文件。首次导入完成后，本机缓存可重复使用；清除微信小程序数据后需要重新导入。
4. 宝可梦→Box→“从截图导入（体验版）”，从相册选择截图。识别后检查食材、性格、技能等字段，使用补全/编辑入口修正。

OCR 使用微信本地推理和离屏 Canvas；需要支持这些 API 的新版微信及真机。开发者工具、部分手机或不兼容模型算子可能无法推理；失败会显示提示，仍可手动录入。没有截图上传到服务器的流程。OCR 的真机表现由使用者验证，编译通过不代表已经完成真机验证。

## 真机验收

- 图鉴/盒子/睡姿墙、五种规划、队伍/比较、七类资料页均可切换；全局设置、弹窗关闭和长列表能正常使用。
- 数字输入、时间、开关、滑块、性格/食材等选择器改变后，计算结果和重新启动后的本机数据保持一致。
- Box 的本机与 sdrice JSON 可导出分享，选择 JSON 或粘贴后可合并/覆盖导入；覆盖前自行保存备份。
- 宝宝效率显示进度、结果，可取消；Worker 分包首次联网加载后再验证断网使用。
- OCR 模型导入、取消选择、未导入模型、正常识别、截图批量导入和待补全字段都有明确反馈。
- 原始木守宫截图应得到 ABB（`[0,1,1]`），合法 ABC 仍应保持 ABC；闪光状态和旧样例同时检查。

## 目录

`src/pages` 是微信入口，`src/components` 是微信控件，`src/platform` 是微信能力适配；功能界面源文件、计算、资料、类型及图片都维护在平级 `core/` 中。`scripts/prepare.mjs` 生成微信适配界面和资源分包。

微信端采用独立本机存储，保持与 Android 相同备份格式，未新增账号与自动同步。发布到微信公众平台仍须使用开发者工具上传，由项目所有者验证和发布。
