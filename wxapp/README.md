# 宝睡助手微信小程序（1.0.3）

Taro 4 + Vue 3 + TypeScript。AppID：`wxa305c12ee6676e08`。

## 编译

在仓库根目录执行：

```powershell
cd wxapp
npm ci
npm run build:weapp
```

开发监听：`npm run dev:weapp`。修改 core 中的界面源文件后重新执行准备/编译命令；生成目录不手动维护。

类型检查：`npm run typecheck`（先执行 `npm run prepare:weapp`）。共享逻辑与 Android 回归：在 `app` 目录执行 `npm ci`、`npm test -- --maxWorkers=1`。

微信 OCR 接口回归：`npm run test:ocr`，检查动态输入的会话创建参数、实际推理尺寸以及失败清理与重试。

用微信开发者工具导入 `wxapp/`，项目配置已经指向 `dist/`；也可以解压本地的 `app/release/PokeSleepAst-1.0.3-weapp.zip`，直接导入解压后的目录。编译产物含五个主页面、图片分包与计算 Worker 分包。无需配置服务端或网络请求域名。小程序没有手动检查更新按钮。GitHub Release 包含 APK、未签名 IPA 与更新清单；含模型的小程序 ZIP 作为本地文件或 Actions artifacts 提供。

## 图片资源

小程序构建会将共享图片及道具、彩庆花、备用精灵图转换为保留透明背景的 PNG，最大边长 128 像素，以预留 OCR 模型的包体空间。原始图片不变。图片内容通过微信 `require.async` 按需加载分包，再写入本机 `USER_DATA_PATH/pokesleep-images`，页面与 OCR 共用这些文件，避免主包直接引用分包图片。首次访问某类图片需要下载对应分包；已缓存图片可离线读取，清除小程序数据后会重新加载。

编译检查会逐张验证图片类别、PNG 文件头、大小、内容哈希、原生异步加载器及主包/分包体积。更新构建后，在开发者工具重新编译并确认预览/体验版已经上传最新产物；如仍看到旧资源，清除工具缓存后重新编译。

## OCR 体验版

编译阶段把原始 det.onnx、rec.onnx 拆为每份不超过 1.6 MB 的模型资源分包，保留全部权重，不量化模型。编译校验会还原模型并与原文件及 SHA-256 对照。主包、单个分包限制为 2 MiB，普通小程序总包按 30 MiB 检查（服务商代开发仍需按其平台额度检查）。

宝可梦→Box→“从截图导入（体验版）”，从相册选择截图。首次识别按需加载模型分包，自动还原到本机缓存；不需要用户选择模型文件，“我的”页面不显示模型导入模块。缓存以模型内容哈希命名，版本变化后自动加载新模型。识别后检查食材、性格、技能等字段，使用补全/编辑入口修正。

OCR 使用微信本地推理和离屏 Canvas；需要支持这些 API 的新版微信及真机。开发者工具、部分手机或不兼容模型算子可能无法推理；失败会显示提示，仍可手动录入。没有截图上传到服务器的流程。OCR 的真机表现由使用者验证，编译通过不代表已经完成真机验证。

原模型具有动态输入轴，创建微信推理会话时按真实输入名 `x` 指定 `typicalShape`：检测模型 `[1,3,640,640]`，识别模型 `[1,3,48,320]`。每次推理仍传入实际图片尺寸，不改变原模型或权重。加载报错会标明文字检测/识别模型，便于真机定位转换兼容问题。

## 真机验收

- 图鉴/盒子/睡姿墙、五种规划、队伍/比较、七类资料页均可切换；全局设置、弹窗关闭和长列表能正常使用。
- 数字输入、时间、开关、滑块、性格/食材等选择器改变后，计算结果和重新启动后的本机数据保持一致。
- Box 的本机与 sdrice JSON 可导出分享，选择 JSON 或粘贴后可合并/覆盖导入；覆盖前自行保存备份。
- 宝宝效率显示进度、结果，可取消；Worker 分包首次联网加载后再验证断网使用。
- OCR 模型首次自动加载、加载失败重试、正常识别、截图批量导入和待补全字段都有明确反馈。
- 原始木守宫截图应得到 ABB（`[0,1,1]`），合法 ABC 仍应保持 ABC；闪光状态和旧样例同时检查。

## 目录

`src/pages` 是微信入口，`src/components` 是微信控件，`src/platform` 是微信能力适配；功能界面源文件、计算、资料、类型及图片都维护在平级 `core/` 中。`scripts/prepare.mjs` 生成微信适配界面和资源分包。

微信端采用独立本机存储，保持与 Android 相同备份格式，未新增账号与自动同步。发布到微信公众平台仍须使用开发者工具上传，由项目所有者验证和发布。

两端分段按钮共享等分 Grid；生产资料菜单每行四项并自动换行。App 保持 CSS 像素布局；小程序采用 375 设计宽度（375 对应 deviceRatio=2），原生输入框明确 border-box 和 100% 最大宽度。副技能使用带稀有度颜色的 PNG 和原生 image，避免 CSS 遮罩引用分包。

当前开发者工具的 AppID 文件额度可能回退到 10 MiB（工具按 runtimeAttr.setting.Uint32MaxFileStorageSizeInMB / MaxFileStorageSize 取额度，缺失时默认 10）。原模型共约 15.6 MB，额度不足时会显示提示；这不影响模型编译入包。请在微信真机验证模型恢复及推理。
